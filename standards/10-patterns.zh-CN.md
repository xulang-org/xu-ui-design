# 页面模式

页面模式组合基础组件，展示完整任务。所有项目名、记录和状态都是可辨认的演示数据，不连接真实仓库。

## 组件组合与排版定式

在组装完整页面前，优先使用预设的六类组件组合定式，避免临时拼凑内边距、字号或对齐方式：

- **操作簇与分段组（`.xu-cluster` / `.xu-button-group`）**：同组动作按钮水平间距 `8 px`（`space-2`），按「主操作 → 次要操作 → 轻量操作 → 危险操作」从左到右排列；视图切换或图表模式切换使用分段组（`.xu-button-group`），以 `aria-pressed="true"` 标示当前激活项。
- **检索与筛选工具栏（`.xu-toolbar`）**：由「主搜索框（自适应伸展）+ 紧凑下拉筛选（`144 px`）+ 尾部主操作按钮」组成。容器使用 `align-items: flex-end`（原生 `layout.CROSS_END`），使带上方标签的输入框与无标签按钮在底部 `40 px` 控件高度上精确对齐。
- **表单栈与双栏网格（`.xu-stack` / `.xu-form-grid`）**：单列字段栈间距 `20 px`（`space-5`），双栏并排间距 `32 px`（`space-8`）。每个字段严格遵循「标签（`14 px` `600`）→ 输入控件（`40 px`）→ 帮助或错误文案（`14 px`）」三层垂直韵律（内部间距 `8 px`），复选与开关项独立成行。
- **三段式卡片面板（`.xu-card`）**：对应原生 `widgets.CardRegions`，由 `.xu-card-header`（左侧 `16 px` 标题与 `12 px` 副标题、右侧状态徽标）、`.xu-card-body`（主体表单、图表或键值规格行 `.xu-kv`）和 `.xu-card-footer`（左侧 `12 px` 等宽状态回执、右侧 `.xu-cluster` 操作簇）组成。
- **结构化列表行（`.xu-list` / `.xu-list-row`）**：对应原生 `widgets.ListRow`，每行采用三列排版——前导 `20 px` 语义图标、中间主标题（`14 px` `500`）与次级说明（`12 px` `muted`）上下堆叠、右侧等宽元数据与行级轻量按钮。
- **主从工作台（Split Workbench）**：以分栏器或导航轨划分左轨（树／分类）与右主区（页签 → 工具栏 → 表格或图表 → 分页状态栏），保持单一主滚动区。

## 设置页面

按“基础信息 → 行为偏好 → 保存结果”排列，字段标签在上，帮助文字跟随字段。更改设置先保留草稿；保存成功后显示明确结果，存储失败保留输入并允许重试。示例本地存储键为 xu-ui-demo-settings；不使用后端 API。

保存按钮原位确认，结果保留在下方；再次编辑立即回到未保存状态。

验收：刷新后读取已保存内容；不合法名称阻止保存；禁用存储时显示失败，不伪装成功。示例不保存个人信息或凭据。

## 数据列表

顺序为“标题和创建入口 → 搜索 → 状态筛选 → 数据表 → 结果数量”。列名说明含义；文本左对齐，数字右对齐；行内操作说明目标。优先 table 保留语义，窄屏让表格容器单独滚动。

验收：关键词和状态共同过滤；无结果显示清空筛选；详情按钮显示对应演示项目；排序按钮带 aria-sort 的列标题。状态文字不能被图标代替。

创建入口在当前页打开本地演示表单，空白或重名错误保留在字段旁。成功后插入一条草稿记录、清除搜索和状态筛选并聚焦新行名称。记录只在当前页面保留，刷新重置，不创建真实仓库。

## 空状态

说明当前情况、导致它的原因和可以做的下一步。初始空状态提供创建入口；筛选空状态提供清空筛选。不能把“无权限”“网络错误”和“尚无数据”都写作“暂无数据”。

## 适配原则

移动端保留主要动作和错误说明；表单变单列；可横向滚动的数据仍有可见标题。不把桌面画布按比例缩小为不可读的截图。示例中的移动预览是真实 DOM 容器，浏览器整体窄屏也必须检查。
