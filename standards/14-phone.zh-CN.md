# 移动端与 Phone 自适应

XU 生态的移动端界面在保留 XUUI 清晰度、对比度与宣纸／曜石／朱砂语义色体系的前提下，针对手机竖屏、横屏与折叠屏视口，显式规范布局、导航、触控人因、滚动物理与系统插槽。移动端规范不应把桌面端界面强行缩放塞入小屏，而应建立统一的宿主安全区与自适应脚手架模型。

## 坐标系与安全区

- 布局与交互坐标一律使用逻辑密度无关单位（`1 px` CSS ≈ `1 dp` Android ≈ `1 pt` iOS）。物理像素倍率由宿主按 `devicePixelRatio` / 显示密度缩放，不改变上层组件尺寸基准。
- 每一帧与视口尺寸变化事件须区分两组系统插槽：
  - **安全区（`safe_area` / `viewPadding`）**：持久存在的系统遮挡区域，包括顶部状态栏／刘海／灵动岛（`top`）、底部手势指示条（`bottom`），以及横屏侧边开孔（`left` / `right`）。
  - **软键盘 / 输入法（`view_insets.bottom`）**：输入法与候选词栏弹出时产生的临时底部遮挡高度。
- **全面屏边缘延伸约定**：背景画布（`canvas` / `surface`）与模态遮罩必须延伸到系统透明栏下方，铺满屏幕物理边缘；可交互控件、顶栏、导航栏、Snackbar 与抽屉内容则避让安全区边界。不要在宿主层把画布强行裁切在盒内或硬编码脱离主题的底色填充。

## 自适应外壳与导航层级

移动端外壳按当前可用宽度与方向动态切换结构，而不是把一种导航条写死在所有设备上：

| 视口 / 形态 | 主导航方式 | 内容区域布局 | 外壳尺寸基准 |
| --- | --- | --- | --- |
| 紧凑竖屏（宽度 `< 600 px`） | 底部导航栏（`3–5` 个一级目标） | 单栏滚动或堆叠视图 | 顶栏 `48–56 px` + `safe_top`；底栏 `64 px` + `safe_bottom` |
| 横屏／宽屏（宽度 `>= 600 px` 或高度受限） | 左侧导航轨（Navigation Rail，`72–80 px` + `safe_left`） | 单栏流式或主从双栏视图 | 紧凑顶栏 `48 px`；不再叠加底部导航栏 |
| 推入的二级详情路由 | 左上角返回操作 + 宿主侧滑／返回手势 | 聚焦详情内容（按需隐藏底栏） | 保留原一级页签的滚动位置与表单草稿状态 |

- 底部导航栏限制在 `3–5` 个同级核心目标；每项包含线性图标（`20–24 px`）与简短标签，并通过 `--xu-brand-soft` 与 `--xu-brand` 激活态胶囊共同区分选中状态，禁止仅靠颜色提示。
- 维护明确的路由栈（`push` / `replace` / `pop`）：切换底部一级页签时保留各自滚动偏移与输入草稿，不重置页面。
- 联动应用生命周期（`resumed` / `inactive` / `paused`）：切入后台或打断交互时立即取消瞬时按压高亮与进行中的惯性拖拽，同时保留业务输入与持久化错误提示。

## 平台姿态与双端习惯

XUUI 通过[色彩与主题](02-color.zh-CN.md)保持跨端视觉一致，同时在操作路径上尊重 iOS 与 Android 的人因习惯：

- **顶栏与返回语义**：
  - **iOS 姿态**：简短标题居中对齐（根页面可使用大标题随滚动收起），左上角提供返回箭头与标签，并支持屏幕左边缘向右轻扫返回。
  - **Android 姿态**：`AppBar` 标题左起对齐，左侧返回按钮保持 `48 × 48 dp` 触控区，并与系统预测返回（Predictive Back）对齐按 `输入法 → 抽屉／浮层 → 路由出栈 → 退至后台` 的顺序响应。
- **系统状态栏对比度**：暗色主题下配置浅色系统状态图标（`--xu-canvas` `#100e12` 铺满边缘）；亮色主题下配置深色系统状态图标（`#f6f3ef` 铺满边缘）。
- **单主拇指操作**：当页面存在唯一高频创建或运行任务时，至多放置一个主强调按钮／浮动操作按钮（`48–56 px`，`--xu-brand` / `--xu-on-brand`），位于底部导航栏与安全底部上方易触达区域。

## 触控人因与动态字阶

- **最小可触控目标**：遵循[可访问性与动效](11-accessibility.zh-CN.md)的 `--xu-target-min`（`44 × 44 px` 底线），**Android 端要求不低于 `48 × 48 dp`**（对应 `--xu-control-lg`）；相邻交互目标之间至少保留 **`8 px`（`--xu-space-2`）** 间距，防止拇指误触。
- **移动端节奏与留白**：页面左右安全内边距取 `16–20 px`（`space-4` 至 `space-5`）；表单项垂直间距取 `16–20 px`；常规双行列表行最小高度为 `64–72 px`，文案容器配置 `min-width: 0`，保证长文本换行或安全省略而不引起整页横向溢出。
- **禁止依赖悬停操作**：所有关键操作不得隐藏在 hover 浮层、悬停提示或右键菜单中；操作入口须直接可见，或收敛到尺寸至少 `44 px` 的显式操作菜单触发器中。
- **动态字体与方向适应**：在 `1.0x` 到 `1.5x+` 系统字体放大与 `320 px` 极窄宽度下，卡片与列表行须随文本自然增高，不得固定行高裁切内容。排版与间距基础见[字体与排版](03-typography.zh-CN.md)和[布局与间距](04-layout.zh-CN.md)。

## 滚动物理与手势判别

- **拖拽阈值（`8 px` / `8 dp` slop）**：位移小于 `8 px` 时保留点击判定；一旦主轴位移越过阈值，滚动容器立即接管手势并取消子元素的按压高亮，确保快速滑动列表不会误触发点击。
- **惯性抛掷（Fling）与回弹边界**：手指高速离手后按速度衰减曲线继续惯性滚动；惯性过程中手指再次按下应立即停住滚动，而不直接穿透点击当前行。
  - **iOS 姿态**：边缘采用弹性过卷回弹（`bouncing`），并伴随短暂显现的右侧滚动条。
  - **Android 姿态**：边缘采用阻尼夹紧或拉伸反馈（`clamping`），并伴随短暂显现的边缘滚动条。
- **横纵轴冲突仲裁**：越过拖拽阈值后按主运动轴锁定手势方向，防止横向轮播／边缘返回手势与纵向列表滚动相互抢占。

## 底部抽屉、软键盘与反馈

- **模态底部抽屉（Bottom Sheet）**：
  - 顶部居中放置抓手条（`36 × 4 px`），明确标题与可触及的关闭按钮（`>= 44 px`），底部 `surface` 背景向下延伸铺满至物理屏底，遮罩使用 `--xu-overlay`。
  - 支持关闭按钮、点击遮罩、下滑超过抽屉高度 `30%` 或达到向下速度阈值关闭，以及键盘 `Escape` ／系统返回键关闭；关闭后将焦点恢复至原触发器。
  - 破坏性确认沿用[反馈与浮层](09-feedback.zh-CN.md)约定，默认聚焦取消且不嵌套第二层确认模态框。
- **软键盘 / IME 避让**：当 `view_insets.bottom > 0` 时，应缩减可滚动表单区域高度并将当前聚焦输入框及主提交按钮滚入可视区；打开中的底部抽屉须同步上抬，不被输入法遮挡底端操作栏。
- **移动端文本输入与 IME 组合输入**：输入框高度不少于 `48 px`（`phone_input_height`），提供清晰标签、不少于 `44 px` 的清空按钮（`phone_touch_target`）、明确的聚焦描边（`focus`）以及报错后原地保留用户输入的持久内联校验（`danger`）。输入法预编辑串（preedit / composing）须与已提交文本以独立下划线明确区分，并在点击完成或场外失焦时干净落字或收尾；系统返回按「软键盘 / 活跃输入 -> 底部抽屉 -> 二级详情页 -> 应用退后台」顺序逐级收起。
- **Snackbar 与阻断错误**：瞬时非关键回执悬浮在 `bottom_bar_height + safe_bottom + 12 px` 之上，至多提供一个“撤销／重试”动作，不得覆盖底部导航或抢占焦点；表单校验失败与保存错误须原地持久保留，见[反馈与浮层](09-feedback.zh-CN.md)。

## 原生映射与验收

- 生成文件 `xu/xuui_tokens/mod.xu` 已提供双主题语义色与移动端基础度量函数（`canvas`、`surface`、`brand`、`brand_soft`、`control_border`、`phone_touch_target`、`phone_bar_height`、`phone_nav_height`、`phone_rail_width`、`phone_gutter`、`phone_sheet_radius`、`phone_input_height`），使 `#ui/phone` 与原生画布渲染可直接对齐 Web 标准。
- **能力边界声明**：本设计库展厅中的浏览器示例用于验证竖屏／横屏自适应切换、安全区边界、软键盘避让示意、校验失败保留输入内容、路由进退、底部抽屉焦点恢复与 Snackbar 位置；真实触控 slop、速度惯性、输入法窗口回调（`UITextInput` / `InputConnection`）、透明系统栏与原生返回手势由宿主运行时（`#ui/phone`、iOS `UIKit`/`WKWebView`、Android `WebView`/原生组件）负责实现与验收。
- **验收要点**：`320 px` 至横屏宽视口下零整页横向溢出；亮暗双主题前景／背景与遮罩对比度通过校验；实机真机上的 VoiceOver 与 TalkBack 读屏播报仍为独立人工验收门槛，不被网页自动化扫描替代。
