# 进度条与加载指示 Progress

在不打断相邻操作的前提下传达确定进度或有界异步耗时状态。以下为组件设计与交互契约；展厅中的浏览器实现与原生边界分别说明。

## 结构

- 任务名称与可选状态说明
- 确定进度轨道与比例填充条（`role="progressbar"`）
- 轨道旁的等宽数字百分比或步骤计数
- 面向未知时长任务的旋转指示器（`aria-busy`）

## 状态矩阵

| 状态 | 必须满足 |
| --- | --- |
| 初始态（0%） | 显示完整轨道边框与初始文字说明，`aria-valuenow="0"` |
| 进行中（1% - 99%） | 填充宽度与等宽百分比数字同步更新，`aria-valuemin="0"`、`aria-valuemax="100"` |
| 完成态（100%） | 平滑切换至成功语义色并提示任务完成 |
| 暂停 / 失败态 | 切换为警告或危险语义色并提供重试／恢复动作，禁止无限空转 |
| 不确定 / 忙碌态 | 旋转指示器搭配明确的等待文案；一旦已知百分比即切换为确定进度条 |
| 减少动效 | 停止旋转与宽度过渡动画，仅即时更新位置与文字百分比 |

## 键盘行为

- 纯展示型进度条不进入 Tab 焦点顺序，减少无意义的键盘停留。
- 关联的推进、暂停、重置或重试按钮遵循标准 Tab 聚焦与回车／空格触发规则。
- 关键阶段完成通过温和实时区域（`aria-live="polite"`）播报，不抢夺用户当前焦点。

## Token 与尺寸

轨道采用 `--xu-subtle` 与 `--xu-border`，填充使用 `--xu-brand`、`--xu-success`、`--xu-warning` 与 `--xu-danger`，两端圆角采用 `--xu-radius-full`；移动端对应 `phone_progress_height`（`6 dp`）。百分比数字强制使用等宽数字排版，防止数值跳动引发布局偏移。

## 原生映射

对应 `widgets.Progress` / `widgets.ProgressBar` 与 `#ui/phone` 的 `phone.progress_bar`；原生端不确定加载动画由宿主绘制节拍驱动并遵守系统减少动效设置。

## 验收

- 可在展厅中交互切换 0%、推进中、100% 完成以及告警／重置等完整生命周期。
- 每个阶段都能读取到准确同步的 `aria-valuenow`、`aria-valuemin` 与 `aria-valuemax`。
- 进度与忙碌态在 320 px 窄屏下折行自然，不依赖单一动画或颜色表达状态。
- 浏览器回归校验步骤按钮键盘操作、实时播报与双主题 WCAG 2.2 AA 零违规。
